# 業務フロー

## 作成日
2026-05-17

## 入力ドキュメント
- `outputs/02_business_structure.md`

## このドキュメントの位置づけ

本プロジェクトは個人ツール限定の**データ可視化サービス**であり、商流・金流・物流が「該当なし」のため、業務フローは情報流を中心とした以下の 2 つの主要フローで構成される:

- **F2 利用フロー(メイン)**: ユーザーが MAP を見て意思決定する
- **F1 データ更新フロー(裏方)**: 月次バッチで現在値・予測値を更新する
- F3 共有フローはシステム機能を持たない人的やりとりのため、参考記述のみ

---

## メインフロー: F2 利用フロー

### 概要

ユーザー(H-01)が MAP を開き、指標・年次を切り替えながら 47 都道府県を比較し、移住先候補を絞り込むメインフロー。

### トリガー

- ユーザー(H-01)がアプリにアクセス(任意のタイミング)

### 正常系ステップ

| # | アクター | アクション | 4 流影響 |
|---|--------|----------|--------|
| F2.1 | H-01 → S-03 | アプリ起動 | 情報流: セッション開始 |
| F2.2 | S-03 → DB | 最新の現在値・予測値・出典情報を取得 | 情報流: DB → S-03 |
| F2.3 | S-03 | 47 都道府県の初期 MAP を描画(デフォルト指標 = 物価指数、デフォルト年次 = 現在値) | 情報流: 画面に出力 |
| F2.4 | H-01 → S-03 | 指標切替(7指標から1つ選択) | 情報流: 該当指標で再描画 |
| F2.5 | H-01 → S-03 | 年次切替(現在 / 3年 / 5年 / 10年) | 情報流: 該当年次で再描画(主要4指標のみ予測値あり) |
| F2.6 | H-01 → S-03 | 「モデル根拠」ページ閲覧(任意) | 情報流: モデル詳細表示 |
| F2.7 | H-01 | 複数指標・年次を比較して都道府県候補を絞り込む | — |
| F2.8 | H-01 → H-02 | (任意)画面共有 / スクリーンショットで意見交換 | F3 として参照 |

### タッチポイント(画面紐付け)

| Step | タッチポイント | 想定画面 |
|------|------------|--------|
| F2.3 | MAP 表示 | `MainMap` 画面(throwaway スケッチは Phase 4 以降) |
| F2.4 | 指標切替 UI | `MainMap` 画面内のセレクタ |
| F2.5 | 年次切替 UI | `MainMap` 画面内のボタン群(UX-D-03 でボタン推奨) |
| F2.6 | モデル根拠ページ | `ModelDetail` 画面 |

> [throwaway] Phase 3 スケッチ — 捨てる前提。配色・レイアウト最適化の議論はしない。

### 補償経路

| ID | 例外 | 補償 |
|----|------|------|
| C-06 | F2.2 DB 接続失敗 | ローカルキャッシュ表示 → なければエラー画面 + 「数分後に再アクセス」案内 |
| C-07 | F2.3-2.5 描画失敗 | 単純再描画 retry → 連続失敗時はエラーバナー |

## サブフロー: F1 データ更新フロー(裏方)

### 概要

月初のバッチで全データソースから取得・正規化し、主要4指標について AI 予測モデルを再学習・予測値を生成する自動化フロー。

### トリガー

- 月初スケジューラ起動(例: 毎月1日 02:00 JST)

### 正常系ステップ

| # | アクター | アクション | 4 流影響 |
|---|--------|----------|--------|
| F1.1 | スケジューラ → S-01 | ETL バッチを起動 | 情報流: ジョブ開始 |
| F1.2 | S-01 → X-01〜X-06 | 各データソースから API/ファイル取得 | 情報流: 外部 → S-01 |
| F1.3 | S-01 | 都道府県コード・単位・型を統一(正規化) | 情報流: 内部処理 |
| F1.4 | S-01 → DB | 現在値テーブルに upsert、履歴テーブルに append | 情報流: S-01 → DB |
| F1.5 | S-01 → S-02 | 主要4指標の再学習をトリガー | 情報流: 通知 |
| F1.6 | S-02 | 時系列モデル(具体は Phase 4)で再学習 | 情報流: 内部処理 |
| F1.7 | S-02 | R² / MAE を計算してモデル評価 | 情報流: 評価ログ記録 |
| F1.8 | S-02 | R² ≥ 0.6 を満たす指標のみ予測値生成へ進む(R1.4 / R2.1) | 情報流: 品質判定 |
| F1.9 | S-02 → DB | 47都道府県 × 4指標 × 3時点(3/5/10年) を upsert | 情報流: S-02 → DB |
| F1.10 | S-01 / S-02 | 成功・失敗ログを記録 | 情報流: 監査ログ |

### 補償経路

| ID | 例外 | 補償 |
|----|------|------|
| C-01 | F1.2 外部 API/CSV 応答失敗 | 指数バックオフで Retry 最大 3 回 → 失敗時は前回値保持 (R1.3) + UI「未更新」表示 |
| C-02 | F1.2 3 回連続失敗 | UI に警告通知 (R2.2)、バッチログにも記録 |
| C-03 | F1.4 DB 書き込み失敗 | 短時間で Retry → 失敗時はトランザクション巻き戻し、旧データ維持(整合性優先) |
| C-04 | F1.6-1.8 R² < 0.6 で品質未達 | 該当指標の予測値表示を抑止し「予測なし」を UI 表示 (R1.4) |
| C-05 | F1.6 学習プロセス失敗 | Retry 1 回 → 失敗時は旧モデルを保持し旧予測値を維持 |

### 判断ガイドの適用

- データのライフサイクルは以下のように仮定(Phase 4 で確定):
  - **現在値テーブル**: master 性(月次上書き) — 補償経路は Retry のみ
  - **履歴テーブル**: append_only_history — Cancel / Reverse 免除
  - **予測値テーブル**: transactional(月次再生成) — 補償経路は Fallback「予測なし」表示
- 主経路に Confirm(購入確定等)がないため、**Cancel / Reject / Modify / Reverse は不要**

## 参考: F3 共有フロー

### 概要

H-01 が H-02(配偶者・家族・友人)に MAP を見せて意見交換する**人的な共有**。システム機能は持たない。

### 想定パターン

- 画面の同席閲覧(物理的に隣で見る、ビデオ通話で画面共有)
- スクリーンショットの手動共有(LINE 等の外部メッセンジャー経由)
- PDF/URL 共有等の機能化は **Phase 3 ではスコープ外**(UX-D-02 として Phase 4 以降で再検討余地)

### 補償経路

- なし(システム外の人的行為)
