## テスト戦略

| レベル | フレームワーク | 対象 | 実行頻度 |
|--------|------------|------|--------|
| Unit | pytest | 純粋関数・小モジュール(normalize_data, indicator_matrix 等) | コミット時 + CI |
| Integration | pytest + DuckDB in-memory | DB を介する処理(upsert, ETL, モデル学習・推論) | コミット時 + CI |
| Smoke | pytest + streamlit-testing-utils | Streamlit アプリ起動・主要 UI 描画 | 日次 + CI |
| Manual | 人手 | UX-D-04 ヒートマップ階層、UI 全体感、色覚配慮 | リリース前のみ |

カバレッジ目標: line ≥ 70%, branch ≥ 60%(個人ツールとして現実的な水準)

---

## テストデータ戦略

- **マスタ**: `seeds/` の本番同等を使用
- **時系列データ**: 合成データ(`tests/fixtures/synthetic_history.py`)で再現可能性確保
- **外部 API**: pytest-mock + httpx-mock でレスポンス固定化

## CI/CD

### `ci.yml`(コミット時)

```yaml
- uv sync
- ruff check .
- mypy app/
- pytest tests/unit tests/integration
- streamlit-testing(smoke)
```

### `monthly-batch.yml`(月初 02:00 JST)

```yaml
- uv sync
- python scripts/run_batch.py
- 失敗時は GitHub Actions の job 失敗通知が走る
```
