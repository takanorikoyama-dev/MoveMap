# 🎤 MoveMap ピッチデッキ案

> 顧客 / 採用担当者 / 社内勉強会への **8 スライド** 構成案。
> 「何のスライドに何を載せるか」+「話し方のヒント」+「想定質問」をセットで整理。
> このドキュメントを元に PowerPoint / Google Slides / Canva で実物を作るのが最短。
>
> 最終更新:2026-06-05(mode C 公開承認後の構成)

---

## 全体構成(8 スライド + 補足)

| # | スライド | 役割 | 所要時間 |
|---|---|---|---|
| 1 | タイトル + キャッチ | 第一印象 | 15 秒 |
| 2 | 課題(Problem) | 共感を得る | 1 分 |
| 3 | 解決(Solution) | 何を作ったか | 1.5 分 |
| 4 | デモ(Live or 動画) | 触ってもらう | 2 分 |
| 5 | アーキテクチャ | 技術の裏側 | 1.5 分 |
| 6 | データ + 信頼性 | データの根拠 | 1 分 |
| 7 | 倫理・法務・計測 | 公開する責任 | 1 分 |
| 8 | 学び + 次の打ち手 | 振り返り + 展望 | 1 分 |

合計 **約 10 分**(質疑応答 5-10 分)

## スライド 1:タイトル + キャッチ

### 載せる
- タイトル:**MoveMap** — 地方移住MAP
- サブ:全国 47 都道府県を 9 観点で比較・診断・予測する
- アクセス URL:`movemap.streamlit.app`
- 制作者 + 制作期間(2026-05-16 〜 2026-06-05、約 20 日)

### ビジュアル
- ヒーローのスクリーンショット(海岸+灯台、「まだ知らない、わたしのまち。」のオーバーレイ)

### 話し方のヒント
- **30 秒のフックを最初に**:「『地方移住したいけど、どこが自分に合うか分からない』を、データと AI で 5 分で解決する個人開発ツールを作りました」

## スライド 2:課題(Problem)

### 載せる(4 つのギャップ)
| ギャップ | 既存ツールの限界 |
|---|---|
| 情報が散在 | 自治体 HP / SUUMO / 田舎暮らしの本 がバラバラ |
| 判断軸がない | データ羅列だけで意思決定支援が弱い |
| 将来が見えない | 出生数・物価・地価の予測が無い |
| 公開・共有しづらい | 個人ツール前提のものが多い |

### ビジュアル
- 散在する Web サイトのアイコン群 → MoveMap への矢印で集約イメージ

### 話し方のヒント
- 「私自身、親世代の移住相談に乗った時にこの問題を実感しました」(自己の動機を添えると説得力UP)

---

## スライド 3:解決(Solution)

### 載せる
- **9 観点の偏差値化 → 住みやすさスコア**
- **AI 予測** で 3 / 5 / 10 年後を可視化
- **5 問の診断** であなたに合う 3 県を提案
- **完全無料・無認証で公開**

### ビジュアル
- 9 観点のアイコンを並べる → ランキング表のスクショ → 診断画面の例

### 話し方のヒント
- 「**データ × AI × UX** の 3 要素を組み合わせて、『どこが自分に合うか』を 5 分で導けます」

---

## スライド 4:デモ(Live or 動画)

### Live demo の流れ(3 分)
1. **ホーム**:ヒーロー画像のスライドショー → バナーから「診断する」
2. **診断**:5 問回答 → 結果で 3 県提案 + 重み自動セット
3. **ランキング**:診断結果を反映した全 47 県の順位
4. **詳細**:1 県の 9 観点 × 4 時点を表で確認、ヒーロー画像で雰囲気を伝える
5. 戻る → 「もう一度違う条件で試してみますね」

### 想定質問への準備
- 「データはどこから?」→ スライド 6 で詳述
- 「予測の精度は?」→ R² 評価を AI 予測タブで公開
- 「個人情報は?」→ スライド 7 で詳述

## スライド 5:アーキテクチャ

### 載せる(2 つの図)

#### 図 1:外部 API → DB → UI
```
[e-Stat / 国交省 / WAQI / Wikipedia]
    ↓ 月次バッチ
[DuckDB: 423 件 + 履歴 + 564 件予測]
    ↓
[Streamlit UI: ホーム + 6 セクション]
    ↓ Cookie 同意済みのみ
[Google Analytics 4]
```

#### 図 2:技術スタック
- **UI**:Streamlit + Plotly(Python 単一言語)
- **DB**:DuckDB(ファイル 1 つ、OLAP に強い)
- **予測**:ARIMA + Prophet アンサンブル
- **画像**:Unsplash + Wikimedia(CDN 直リンク)
- **公開**:Streamlit Cloud(無料)+ GitHub Pages(SEO 用 LP、計画中)
- **計測**:GA4(opt-in、anonymize_ip)
- **AI 駆動開発**:twin-build フレームワーク(Phase 0-8 + DEC ログ + INV)

### 話し方のヒント
- 「Python 単一言語で UI〜ETL〜ML を完結させたので、個人開発でも 20 日で公開まで到達できました」

## スライド 6:データ + 信頼性

### 載せる(データソース 6 つ)
| 指標 | データ源 | ライセンス |
|---|---|---|
| 物価 / 出生 / 治安 / 移動 | e-Stat | 政府統計、公的利用可 |
| 地価 / 賃料 | 国交省 不動産情報ライブラリ | 公開データ |
| 空気質 | WAQI | 表示時クレジット必要 |
| 災害 / 交通 | 国土数値情報 | 公開データ |
| 県の概要 / 市区町村 | Wikipedia / Wikidata | CC-BY-SA |
| ヒーロー画像 | Unsplash / Wikimedia | Unsplash License / CC-BY-SA |

### 信頼性の担保
- **18 の不変条件(INV)**:R² < 0.6 の予測は表示しない、履歴データの改ざん禁止 等
- **232 件のテスト**:単体 / 結合 / smoke、全件パス
- **AI 予測の透明性**:モデル種類・R²・MAE を公開タブで全表示(INV-BIZ-003)

### 想定質問
- 「データの更新頻度は?」→ 月次自動バッチ(GitHub Actions cron)
- 「リアルタイムですか?」→ 月次更新、リアルタイムではない旨を出典に明記

## スライド 7:倫理・法務・計測駆動

### 載せる(3 つの責任)

#### 1. 倫理(免責)
- **「投資助言・不動産助言・移住助言ではない」** 明示(INV-BIZ-006)
- 詳細な免責事項エクスパンダ:不動産公正競争規約 / 金商法 / 移住の各観点

#### 2. 法務(整備済)
- **利用規約**(`outputs/legal/terms.md`、全 11 条)
- **プライバシーポリシー**(`outputs/legal/privacy_policy.md`、全 13 条)
- **フッターから法務リンク導線**(INV-BIZ-008)

#### 3. プライバシー(opt-in 計測)
- 認証なし閲覧専用 = アカウント情報取らない
- **Cookie 同意バナー** → 同意後のみ GA4 注入(INV-BIZ-007)
- IP アドレス GA4 側で匿名化(`anonymize_ip: true`)

#### 4. 計測駆動の運用
- 公開前に **仮説を 2 つ数値で書く**
- GA4 カスタムイベントで `view_change` / `indicator_change` / `diagnosis_complete` を取得
- **T+14 日後に振り返り**(当たり / 外れを記録、次の打ち手を仮説化)

### 話し方のヒント
- 「**作って公開して終わり、ではない**」「計測 → 学習 → 改善のループを回すために設計しました」

## スライド 8:学び + 次の打ち手

### 載せる(振り返り)

#### この 20 日で身についたこと
- twin-build Phase 0-8 の構造化開発(課題 → 要件 → アーキ → 実装 → レビュー)
- データソースの probe(API 仕様は実レスポンスで決まる)
- DEC(意思決定ログ)で「なぜ」を残す習慣
- 法務・倫理を含む公開判断のフレームワーク
- AI 駆動開発(Claude Code + twin-build MCP)での介在価値の整理

#### 短期(~1 ヶ月)の打ち手
1. **47 県の魅力記事を自動生成 + GitHub Pages 公開**(SEO Tier 2)
2. **計測駆動の T+14 仮説検証** → 振り返りで学習
3. **note 記事 / Qiita 技術記事** で被リンク + 個人ブランド

#### 中期(検討)
1. AI 移住アドバイザー(Claude API でチャット)
2. 市区町村ドリルダウン
3. 物件 / 求人 / 自治体連携

### 話し方の締め
- 「**個人開発でも、設計判断の蓄積 + 計測駆動の運用 + AI 活用 で、ポートフォリオ作品が運用可能なレベルになる**ことを実証しました」

## 補足:想定質問とその回答

### 技術系
| 質問 | 回答の方向性 |
|---|---|
| なぜ Streamlit? React じゃダメ? | Python 単一言語 + 個人開発で最速。SEO は別 LP で補強 |
| 予測の精度は? | R² で評価、0.6 未満は表示しない(INV-BIZ-003) |
| データの新鮮度は? | 月次自動バッチ。リアルタイムでない旨を明記 |
| AI 駆動開発の介在価値は? | 課題設定 / 設計判断 / データ probe / 法務判断 / QA は人間。コード形は AI |
| マルチユーザー対応は? | 認証なし閲覧専用、現状はマルチユーザー前提なし |

### ビジネス系
| 質問 | 回答の方向性 |
|---|---|
| 収益化は? | しない(個人ポートフォリオ作品、DEC-016 で商用拡張は対象外) |
| 競合との差別化? | データ統合 + AI 予測 + UX、特に「9 観点偏差値化」と「個人最適化重み」 |
| 自治体に売れる? | B2B SaaS / API としては設計可能だが本プロジェクトのスコープ外 |
| 運用コストは? | ¥0/年(完全無料)。独自ドメインのみ任意 ¥3,000/年 |

### 倫理・法務系
| 質問 | 回答の方向性 |
|---|---|
| プライバシーは? | 認証なし、Cookie opt-in、IP 匿名化、プライバシーポリシー公開 |
| 不動産・投資助言になりませんか? | 免責バナー + 詳細免責(不動産公正競争規約 / 金商法は対象外と明示) |
| データの著作権は? | 公的統計 + Wikipedia(CC-BY-SA)+ Unsplash License、すべて出典明記 |

### 開発プロセス系
| 質問 | 回答の方向性 |
|---|---|
| twin-build とは? | AI 駆動開発のフェーズ管理フレームワーク。Phase 0-8 + DEC ログ + INV |
| AI と人間の分業は? | AI = コード生成、人間 = 課題設定・設計判断・データ probe・法務 / 倫理判断・QA |
| 失敗・限界は? | ① public_safety を後で千人率化、② サイドバー前提を後で UI 刷新、③ Streamlit の HTML サニタイザに悩まされた(全て学びとして記録) |
